## 프로젝트 소개

생성형 AI를 단순한 질문 도구가 아니라, 작은 문제를 실제로 해결하는 도구로 활용해보기 위해 만든 To-do 앱입니다.

필요한 기능과 화면 구조를 직접 정의하고, AI가 작성한 초안을 실행해보며 불편한 점과 오류를 찾았습니다. 이후 요구사항을 더 구체적으로 전달하고 결과를 다시 검증하는 과정을 반복해 완성했습니다.

이 프로젝트의 목적은 전문적인 개발 역량을 과장하는 것이 아니라, 비전공자의 관점에서 **문제를 정의하고 AI의 결과를 검증하며 개선하는 과정**을 직접 경험하는 것이었습니다.

## 주요 기능

- 할 일 추가 및 날짜별 관리
- 체크박스를 통한 완료 처리
- 할 일·완성된 일·휴지통 탭 전환
- 모든 섹션에서 내용 수정
- 휴지통 이동, 원래 상태로 복원, 완전 삭제
- 지난 날짜의 미완료 항목을 오늘 화면에서 확인
- 완료된 항목의 기존 날짜 기록 유지
- 브라우저를 닫아도 목록이 유지되는 로컬 저장
- GSAP을 활용한 자연스러운 화면 전환
- 데스크톱과 모바일에 대응하는 반응형 디자인
- 앱 아이콘 및 소셜 공유용 오픈그래프 이미지

## 사용 기술

| 기술 | 역할 |
| --- | --- |
| HTML | 앱의 화면 구조와 접근성 요소 구성 |
| CSS | 미니멀한 목록형 디자인과 반응형 화면 구현 |
| JavaScript | 추가·완료·수정·삭제·복원·날짜 처리 로직 구현 |
| localStorage | 브라우저를 닫아도 할 일 데이터가 유지되도록 저장 |
| GSAP | 항목 추가·이동·메뉴 전환 애니메이션 적용 |
| GitHub Pages | 별도 서버 없이 웹앱 공개 |

## 핵심 동작 구조

```text
사용자 입력
   ↓
JavaScript 배열에 할 일 추가
   ↓
현재 날짜와 상태에 맞춰 화면 다시 표시
   ↓
localStorage에 저장
```

각 할 일은 다음과 같은 정보를 가집니다.

```javascript
{
  id: "고유 식별값",
  text: "할 일 내용",
  status: "todo | completed | trash",
  date: "2026-09-05",
  deletedFrom: "삭제 전 상태"
}
```

`deletedFrom`은 휴지통에서 복원할 때 해당 항목이 원래 ‘할 일’과 ‘완성된 일’ 중 어느 곳에 있었는지 기억하기 위해 사용했습니다.

## 제작 과정과 개선 경험

### 1. 요구사항 정의

처음부터 코드를 요청하기보다 필요한 사용자 흐름을 먼저 정리했습니다.

- 상단에 할 일·완성된 일·휴지통 배치
- 목록 왼쪽에 체크박스, 오른쪽에 더보기 메뉴 배치
- 완료·수정·삭제·복원이 서로 자연스럽게 연결되도록 설계

### 2. 초안 실행과 문제 발견

초기 결과물은 카드가 강조된 디자인이어서 원하는 단순한 목록형 화면과 달랐습니다. 또한 더보기 메뉴가 아래 목록과 겹치면 버튼을 누르기 어려웠고, 브라우저 팝업을 이용한 수정 기능도 사용성이 좋지 않았습니다.

### 3. 요구사항 구체화와 수정

- 카드형 화면을 얇은 구분선 중심의 목록형 화면으로 변경
- 열린 메뉴가 다른 목록보다 위에 표시되도록 화면 층 순서 수정
- 팝업 대신 목록 내부에서 바로 수정하고 저장하도록 변경
- 달력에서 날짜를 선택하고 날짜별 할 일을 관리하도록 개선

### 4. 결과 검증

할 일 추가부터 완료, 수정, 휴지통 이동, 복원, 완전 삭제까지 사용자 흐름을 직접 반복하며 상태와 저장 결과를 확인했습니다.

## 배운 점

이 프로젝트를 통해 바이브코딩에서 중요한 것은 AI에게 단순히 “만들어 달라”고 요청하는 것이 아니라는 점을 배웠습니다.

1. 해결하려는 문제와 원하는 동작을 구체적으로 정의해야 합니다.
2. AI가 만든 결과가 요구사항과 일치하는지 직접 실행하고 검증해야 합니다.
3. 오류를 설명할 때 발생 조건과 기대 결과를 명확히 전달해야 더 정확하게 개선할 수 있습니다.
4. 코드를 모두 직접 작성하지 않았더라도 데이터가 저장되고 화면에 반영되는 핵심 흐름은 이해해야 합니다.

## 감사업무와의 연결

이 경험은 반복적인 감사업무를 보조하는 작은 도구를 만드는 과정에도 적용할 수 있다고 생각합니다.

예를 들어 고객사에서 받은 거래처·금융기관 목록의 형식을 통일하고, 중복 항목이나 필수정보 누락을 찾아주는 전처리 도구를 생각해볼 수 있습니다. XBRL 업무에서는 원재무제표와 XBRL 결과의 금액·부호·단위·기간·누락 여부를 비교하는 정합성 검토 도구로 확장할 수 있습니다.

다만 프로그램과 AI는 반복적인 확인을 지원하는 보조수단이며, 회계적 적정성이나 감사증거의 충분성에 관한 최종 판단은 실무자가 수행해야 한다고 생각합니다.

## 프로젝트에서 맡은 역할

- 해결할 문제와 필수 기능 정의
- 참고 화면을 바탕으로 UI 방향 설정
- 생성형 AI를 활용한 코드 초안 제작
- 실제 실행을 통한 오류 및 불편사항 발견
- 수정 요구사항 구체화와 결과 검증
- GitHub Pages를 이용한 웹 배포

> 코드 구현에는 생성형 AI의 도움을 많이 받았으며, 기능 요구사항 정의와 실행 테스트, 오류 발견, 개선 방향 결정은 직접 수행했습니다.

## 실행 방법
